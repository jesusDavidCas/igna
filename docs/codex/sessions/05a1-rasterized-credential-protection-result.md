## Previous Architecture

Team credentials were stored privately in `team_credentials.document_path`, but public signed file downloads rendered a protected response on demand from the original file. PDF credentials were imported with FPDI and then watermarked with additional PDF text instructions, leaving the original PDF page layer beneath the watermark.

## Identified Weakness

The previous PDF protection could leave clean original PDF content available underneath a removable overlay. PDF editors or conversion tools could potentially remove or bypass the added watermark layer and recover the clean credential content.

## Final Architecture

- `document_path` remains the private original credential source.
- A new `protected_document_path` stores a private rasterized PDF derivative.
- PDF originals are rasterized page by page with Poppler `pdftoppm` at 170 DPI.
- Image originals are decoded with GD, EXIF orientation is normalized when available, transparency is flattened to white, and the page is written as JPEG.
- Each raster page receives the IGNA Studio protected-copy watermark directly in the image pixels.
- FPDF assembles the watermarked raster pages into a new protected PDF.
- Public signed download routes only return the stored protected derivative.
- Missing or failed protected derivatives return 404 and never fall back to the original.

## Storage Model

Added nullable/default metadata columns on `team_credentials`:

- `protected_document_path`
- `original_checksum`
- `protected_checksum`
- `protected_generated_at`
- `protection_version`
- `protection_status`
- `protection_error`

The migration is additive, reversible, and preserves existing credential records.

## Rasterization Engine

- Selected engine: Poppler `pdftoppm` CLI for PDF-to-JPEG rasterization.
- Required PHP extension: `gd`.
- Useful PHP extension: `exif` for JPEG/TIFF orientation normalization.
- Existing packages used: `setasign/fpdf`, `setasign/fpdi`, `symfony/process`.
- No dependency installation or upgrade was performed.

Local capability check:

- `imagick`: not available and no longer required.
- `pdftoppm`: available locally.
- `gs`: not available locally.
- `soffice`: available locally for manual DOCX conversion.

## Watermark Implementation

Watermark wording:

- `IGNA Studio`
- `Copia protegida de credencial`
- `Protected credential copy`

The watermark is rendered into each raster page with GD before the final PDF is assembled, so it is not a separate editable PDF text layer.

## Regeneration Lifecycle

Protected derivatives are generated when a credential is uploaded and can be regenerated by an authorized administrator from the team-member edit screen. Regeneration writes a new protected PDF first, then updates metadata. If regeneration fails while an older protected derivative exists, the old derivative remains available and a safe error message is recorded.

## Failure Behavior

When Poppler or GD processing is unavailable or generation fails:

- The original credential remains private.
- The public download route does not return the original.
- New uploads without a protected derivative are not downloadable.
- Existing valid derivatives are preserved during failed regeneration.
- Administrators see safe localized status text, not stack traces or paths.

## Authorization

The existing signed URL and throttling model remains in place. The public credential controller still verifies the credential belongs to the route-bound team member and that the team member is active and the credential is public.

## Production Requirements

Hostinger must provide:

- PHP 8.4 with `gd`.
- Optional but recommended `exif`.
- Poppler `pdftoppm` executable available to PHP's process user.
- Writable Laravel storage and temporary storage.
- Enough memory and execution time for 150-200 DPI page rasterization.

The feature should not be declared production-ready until `pdftoppm` availability is confirmed on Hostinger. Without `pdftoppm`, PDF credential generation fails closed.

Suggested post-deployment verification:

```bash
php -m | grep -E '(^gd$|^exif$)'
command -v pdftoppm
php artisan route:list --except-vendor | grep credentials
```

## Remaining Limitations

Rasterization prevents the previous clean text layer from remaining beneath a removable watermark. It cannot prevent screenshots, photography, manual recreation, OCR of the protected raster pages, or intentional redrawing from the visible raster image.
